# 面试说明

## 一分钟介绍

SmartSupport Agent 是一个电商售后智能客服项目。我使用 LangGraph 管理多轮状态和条件路由，使用 BGE 中文向量与关键词混合检索，再由 DeepSeek 基于引用资料流式回答。订单、物流和退款通过确定性工具执行，高金额退款和高风险问题进入人工工单。系统包含 JWT/RBAC、审计、限流、Prometheus、用户提问与知识缺口分析和 PostgreSQL/pgvector 部署配置。

## 关键设计问题

### 为什么不让大模型直接退款？

LLM 只负责理解和生成。退款资格、订单归属、金额阈值和幂等性由业务服务校验，执行前需要用户确认，高金额请求必须人工审批。

### 为什么采用混合检索？

向量检索擅长同义表达，关键词检索擅长订单号、产品型号和政策名称。混合评分同时保留语义召回和精确匹配。

### 如何避免会话串数据？

LangGraph 的线程 ID 使用 `user_id + session_id`。用户身份来自 JWT，不接受请求体声明的身份。

### 模型不可用怎么办？

知识问题降级为确定性摘要，业务工具不受影响；错误进入执行轨迹和模型观测表。

### 如何发现知识库需要补充什么？

系统统计真实用户提问频次，并读取对应 Agent 回答的知识引用。知识类问题没有引用时会进入知识缺口排行，运营人员可以优先补充出现次数最多的文档。

## 简历描述

独立设计并实现电商售后智能客服平台，基于 LangGraph 构建持久化多轮工作流，结合 BGE 中文 Embedding、关键词检索和 pgvector 实现可溯源 RAG；建设 25 篇结构化文档和 93 个检索分段，接入 DeepSeek 流式生成及订单、物流、退款工具，完成 JWT/RBAC、人工工单、审计、Redis 限流、Prometheus 监控和真实用户提问/知识缺口分析，并使用 3200 条合成问题完成 1000 条离线批量验证，后端 28 项测试通过。

## 三分钟演示顺序

1. 管理员登录并展示知识库和质量看板。
2. 上传一篇文档并查看分段。
3. 返回客服工作台进行带引用问答。
4. 连续查询订单和物流，展示会话记忆。
5. 发起高金额退款，展示风险拦截和工单创建。
6. 在工单中心接单、回复并解决。
7. 展示高频用户提问、知识库缺口和 Prometheus 指标。
